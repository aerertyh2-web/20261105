## 1. 产品目标与核心闭环

建设一个非公开、多用户、邀请码注册的中文个人工作台，服务本人邀请的朋友圈，支持电脑和手机浏览器。

P0 核心动作：

**新建任务 → 到期收到站内及企微提醒 → 完成任务 → 查看本月完成率。**

P0 包含五个主模块和快速便签：

1. 任务管理。
2. 智能提醒与企业微信推送。
3. 仪表盘。
4. 管理后台。
5. 用户体系及个人设置。
6. 快速便签，入口位于仪表盘。

容量设计基线：不超过 100 个用户，单用户不超过 1 万条记录。该数字是容量假设，不代表已经完成压力测试。

## 3. 技术与数据基线

- 后端：Python Flask，应用工厂模式，按模块拆分蓝图、模型、模板和测试。
- 数据库：SQLite；所有连接确保 `journal_mode=WAL`、`foreign_keys=ON`，并设置忙等待超时。
- 数据迁移：Flask-Migrate / Alembic，从工程初始化开始启用，禁止只依赖“首次建表”。
- 服务端渲染：Jinja2 + Bootstrap 5，少量 JavaScript；手动排序使用 SortableJS。
- 密码：使用 **bcrypt** 哈希，不明文保存，密码最短 8 位。
- 界面：全中文；错误提示中文，不向用户显示英文堆栈，完整堆栈写服务端日志。
- 时区：配置固定 `Asia/Shanghai`，应用、调度器、界面和导出均使用东八区。
- 数据库存储：时间字段统一保存 UTC，所有页面和通知展示时转换为东八区；统计按东八区自然日计算。
- 数据目录：数据库为 `data/app.db`；上传文件为 `data/uploads/`；备份临时文件为 `data/backups/`；日志为 `data/logs/`。
- 密钥：`SECRET_KEY`、Webhook 字段加密密钥等通过环境变量提供，不写入 Git，不在页面或命令行显示。
- 会话：登录成功后重新生成会话 ID；登录态 30 天；Cookie 设置 HttpOnly、SameSite=Lax，生产环境开启 Secure。
- 防护：参数化查询、Flask-WTF CSRF、模板自动转义、登录失败锁定、服务端权限校验。
- 列表：所有列表分页，每页 50 条；数据查询必须带当前用户条件，管理后台除外。
- 浏览器：支持最近两年发布的 Chrome、Edge、Firefox、Safari 主流版本。
- 本地启动：提供一条命令或一键脚本，中文 README 写明启动及成功确认方式。
- 生产部署：Zeabur 一键部署，提供 Dockerfile 或等价配置；环境变量包含时区、密钥，数据卷持久挂载 `data/`，HTTPS 必须生效。
- 上线硬门槛：Zeabur 仅运行一个应用实例，不开启多副本；`data/` 必须挂载持久数据卷；密钥环境变量长期保持不变。未满足任意一项不得正式使用。

## 4. 角色、注册与权限

### 4.1 安装与注册

- 首次访问进入安装向导：设置管理员账号和密码 → 设置网站名称 → 完成。
- 安装完成后写入安装标记，向导永久关闭；再次访问安装地址只能进入登录页，不得重复创建管理员。
- 注册字段：用户名、邮箱（选填）、密码（最短 8 位）和邀请码。
- 默认开启注册，且注册必须提供有效邀请码；管理员可关闭全站注册。
- 邀请码存表，支持使用次数限制、剩余次数和删除。
- 登录可使用用户名或邮箱；同一用户名连续 5 次密码错误锁定 15 分钟，成功后清零失败次数。
- P0 不提供 SMTP 自助找回密码；忘记密码联系管理员。
- 管理员忘记密码时，由开发工程师使用 README 中的应急 CLI 方法重置；普通用户不需要执行命令。

### 4.2 权限

| 角色 | 权限 |
|---|---|
| 未登录访客 | 未完成安装时使用安装向导；已安装后只能访问登录和注册页 |
| 普通用户 | 只访问自己的任务、提醒、便签、消息、设置和仪表盘 |
| 管理员 | 拥有普通用户能力，并可管理用户、品牌、邀请码、系统状态和备份 |

权限规则：

- 普通用户访问他人记录时返回 404，避免泄露记录是否存在；访问 `/admin` 返回中文 403 页面。
- 管理员重置某用户密码后，该用户所有登录态立即失效。
- 禁用用户仅影响认证：阻止新登录并撤销现有会话，所有业务数据完整保留，可重新启用。
- 数据隔离是全局约束，P0 及未来所有模块必须继承，不能仅依靠隐藏页面按钮。

## 5. P0 功能行为定义

### 5.1 模块 A：任务管理

#### 字段与分类

- 单日任务：任务名称、分类（工作/生活）、优先级（高/中/低）、截止日期、截止时间（精确到分钟）、备注。
- 页面将日期和时间组合保存为一个截止时刻；列表再按东八区拆分为日期和时间显示。
- 优先级使用颜色区分，同时必须显示文字或图标，不得只依赖颜色。
- 周期任务：每日、每周、每月，保存“下次到期时间”，可暂停和恢复。

#### 行为规则

1. 支持新建、编辑、标记完成和删除。
2. 删除进入回收站，保留 30 天后自动物理清理；可恢复，显示剩余天数，也可手动彻底删除。
3. 逾期任务标红并带“已逾期”文字或图标；任务列表顶部显示逾期横幅，点击可筛选逾期任务。
4. 周期任务不生成未来实例；完成后写入完成历史，并从原到期时间顺延一个周期。
5. 周期任务暂停后不再顺延和提醒；恢复时以原周期规则重新计算下次到期时间，页面显示计算结果。
6. 月末周期按目标月份实际天数处理，例如 1 月 31 日的每月任务，下次为 2 月最后一天。
7. 已完成任务可归档；归档任务不占主列表，归档页支持按任务名称搜索，搜索范围仅限当前用户。
8. 默认按“到期日期和时间升序，再按优先级高到低”排序；用户可切换手动排序，使用拖拽调整并保存顺序。
9. 切回默认排序后保留手动顺序，再次切回手动模式可继续使用。
10. 手动排序只作用于进行中任务；已完成、已归档和回收站不提供拖拽；筛选或搜索状态下禁止拖拽，避免部分列表排序破坏完整顺序。
11. 本月统计包含：本月总数、已完成、待完成、逾期数、完成率。
12. 完成率分母为当月截止的单日任务数，不含周期任务；分母为 0 时显示“暂无任务”，不显示 100%。
13. 同一任务被多个设备同时编辑时，后保存覆盖先保存，页面显示最后更新时间。

### 5.2 模块 B：智能提醒与企业微信推送

#### 三类提醒

| 类型 | 字段与周期 | 提醒规则 |
|---|---|---|
| 纪念日 | 名称、公历/农历日期、备注；农历支持闰月 | 每年重新换算当年公历日期，提前 3 天提醒 |
| 健康提醒 | 名称、内容、每日/每周/每月/单次、提醒时间 | 按周期或单次时间提醒 |
| 缴费提醒 | 名称、金额、每日/每周/每月周期、备注 | 提前 7 天提醒；标记已缴后自动顺延下一周期 |

补充规则：

- 农历使用成熟农历库换算，不能将农历月日当作固定公历日期重复使用。
- 闰月纪念日：当年存在对应闰月时按闰月计算；不存在时默认按同月非闰月计算，并在详情中显示本年度换算后的公历日期。
- 缴费金额以“分”为最小存储单位，避免浮点金额误差；页面以人民币元显示两位小数。
- 标记已缴必须保存本次缴费历史，再顺延下一周期，不生成未来缴费实例。
- 任务也进入提醒闭环：默认在截止日当天北京时间 8:00 生成一次到期提醒，不为任务额外增加复杂提醒规则。

#### 调度与去重

- 正式周期检查任务每天北京时间 **8:00** 运行一次，检查任务、纪念日、健康和缴费提醒。
- 单次健康提醒支持精确到分钟。调度器每分钟只扫描“已到期的单次提醒”，不为每条提醒创建独立调度任务，以满足“5 分钟后测试提醒”的验收并降低重启恢复复杂度。
- 每天 8:00 的正式检查同时作为单次提醒的遗漏补偿；任何扫描都必须先去重再发送。
- 同一提醒、同一到期时间、同一提醒批次使用唯一去重键；调度器重复运行不能产生重复站内消息或企微推送。
- 调度器只运行一个实例，记录上次运行时间、最近成功时间和最近错误；Zeabur 不开启多副本。
- 农历纪念日每次换算后保存下次公历发生日期，但每年必须重新换算，不能永久沿用旧结果。

#### 站内消息

- 顶部导航显示铃铛和未读红点；点击铃铛进入消息列表。
- 进入消息详情自动标记已读；支持“全部已读”。
- 消息详情可跳转到对应任务或提醒。
- 已读消息保留 30 天，之后自动物理清理；未读消息不按此规则清理。

#### 企业微信

- 每个用户在个人设置中填写自己的机器人 Webhook；加密存库，任何页面不得明文展示。
- 保存前可点击“测试连通”，发送一条中文测试消息；测试结果以中文显示。
- 未填写 Webhook 时只进入站内消息，不报错、不反复催填。
- 推送消息统一中文模板：标题 + 内容 + 跳转说明。
- 推送失败记录日志，管理后台可查看最近推送成功/失败数量及失败明细；页面不展示完整 Webhook。
- 推送采用去重、合理错峰和有限重试，防止重复发送及无限重试。

### 5.3 模块 C：仪表盘

- 今日待办任务列表，显示逾期横幅入口。
- 今日提醒事项，合并展示任务、纪念日、健康和缴费提醒。
- 本月完成率进度条，统计口径与任务模块完全一致。
- 快速便签，可直接新建、编辑、完成和删除。
- 学习状态占位卡片，仅显示“学习记录将在后续版本提供”，不可点击，不开发学习记录功能。

### 5.4 模块 D：管理后台

独立入口 `/admin`，仅管理员可见和访问。

1. 用户管理：分页列表、禁用/启用、重置密码；重置后对方全部登录态失效。
2. 品牌设置：网站名称和单版 Logo；仅允许 PNG/JPG，大小不超过 1MB，检查真实文件类型，文件名随机化；全站顶部导航显示同一 Logo 和名称。
3. 邀请码管理：生成并设置可用次数、删除、查看已用/剩余次数；支持全站注册开关。
4. 系统状态：数据库大小、调度器上次运行时间、最近推送成功/失败数、用户数。
5. 推送失败记录：后台可查看失败时间、所属用户、提醒标题和中文错误摘要，不显示 Webhook 明文。
6. 数据备份：使用 SQLite 在线备份 API（`sqlite3 backup` 安全语义），不得直接复制正在写入的数据库；一键生成并下载备份。
7. 备份下载链接短时且一次性有效，下载动作记录日志；普通用户无权访问。
8. 备份包含全部用户数据，操作说明必须提示管理员下载后另外保存到受信任的位置，不得只留在 Zeabur 或当前电脑；P0 不因此增加自动备份或恢复页面。
9. 提供 404/500 自定义中文错误页；权限不足和上传过大分别返回友好中文提示。

### 5.5 模块 E：快速便签

- 字段：内容、创建时间、是否完成；编辑时记录更新时间。
- 操作：新建、编辑、标记完成、删除。
- 删除为直接物理删除，不进回收站；删除前显示确认弹窗。
- 入口位于仪表盘，减少操作层级，优先保证“记录快”。

### 5.6 全局功能与个人设置

- 顶部导航：Logo、网站名、模块入口、消息铃铛、退出登录。
- 移动端宽度小于 768px 时变为底部 Tab：仪表盘、任务、提醒、我的；列表转换为卡片，可点击区域不小于 44px，桌面端不受影响。
- 提供空状态引导、加载转圈、删除确认弹窗和中文表单校验。
- 个人设置：修改密码、企微 Webhook 与测试连通、数据导出。
- 数据导出为 UTF-8 JSON，包含格式版本、导出时间、东八区标识，以及当前用户的任务、完成历史、提醒、缴费历史和便签。
- JSON 使用稳定字段名和明确数据类型，作为日后反向导入的格式；P0 只导出，不实现导入。
- 导出内容不包含密码哈希、Webhook 密文、会话令牌、邀请码、其他用户数据或站点密钥。

## 6. P0 明确不做

以下任何一轮都不得提前实现：

- 万年历，包括农历日历页、黄历、倒计时和月日历页面。
- 多日任务三阶段、节假日自动避让。
- 学习记录、勋章。
- AI 应用/成品管理。
- 网站/服务器/域名资产。
- 账号密码库。
- 资源收藏、羊毛、自动化脚本记录、番茄钟。
- 全局搜索、命令面板。
- 统一标签系统。
- 暗色模式。
- 数据大屏、多语言。
- 真实服务器探测。

注意：纪念日的“农历日期换算”属于 P0 智能提醒，不等于开发万年历；仪表盘“学习状态占位卡片”不等于开发学习记录。

## 7. 数据库表设计

### 7.1 通用约定

- 主键统一为 `id INTEGER PRIMARY KEY`，敏感会话和下载令牌只保存哈希。
- 时间字段使用 `DATETIME` 保存 UTC，展示统一转东八区。
- 用户业务表必须包含 `user_id` 和创建/更新时间；所有查询同时校验归属。
- 任务使用软删除；便签和到期已读消息按需求物理删除；其他记录按业务需要保留状态。
- 外键约束必须开启，结构变更必须生成 Alembic 迁移，不手工绕过迁移修改数据库。

### 7.2 用户、安装与安全

#### `users`：用户

字段：`id`、`username`（非空唯一）、`email`（可空唯一）、`password_hash`（bcrypt）、`role`（`user` / `admin`）、`is_active`、`failed_login_count`、`locked_until`、`last_login_at`、`created_at`、`updated_at`。

索引：`username` 唯一、`email` 唯一、`role`、`is_active`。

#### `user_settings`：用户设置（一对一）

字段：`user_id`（唯一外键）、`wecom_webhook_ciphertext`（可空）、`wecom_configured_at`、`task_sort_mode`（`default` / `manual`）、`created_at`、`updated_at`。

说明：不存主题字段，因为 P0 不做暗色模式；Webhook 永不回显。

#### `auth_sessions`：登录会话

字段：`id`、`user_id`、`token_hash`（唯一）、`created_at`、`expires_at`、`last_seen_at`、`revoked_at`、`user_agent`、`ip_address`。

说明：登录成功后生成新随机会话 ID；默认 30 天有效；支持管理员重置密码或禁用用户时统一撤销。

索引：`token_hash` 唯一、`(user_id, revoked_at, expires_at)`。

#### `invitations`：邀请码

字段：`id`、`code_hash`（唯一）、`code_hint`（列表识别用，不含完整码）、`max_uses`、`used_count`、`created_by`、`created_at`、`deleted_at`。

说明：完整邀请码只在生成后展示一次；注册时原子校验并增加使用次数；删除后不能再注册。

#### `site_settings`：站点设置（单行）

字段：`id`（固定单行）、`site_name`、`logo_path`、`registration_enabled`（默认开启）、`installed_at`、`installation_completed_by`、`created_at`、`updated_at`。

说明：`installed_at` 非空后安装向导永久关闭；只保存 `data/uploads/` 内的 Logo 相对路径。

### 7.3 任务、提醒与便签

#### `tasks`：任务

字段：`id`、`user_id`、`title`、`category`（`work` / `life`）、`priority`（`high` / `medium` / `low`）、`description`、`task_type`（`single` / `recurring`）、`status`（`pending` / `completed` / `paused` / `archived`）、`due_at`、`recurrence_unit`（`day` / `week` / `month`，可空）、`next_due_at`、`manual_sort_order`、`completed_at`、`archived_at`、`created_at`、`updated_at`、`deleted_at`。

约束：

- 单日任务必须有 `due_at`，周期字段为空。
- 周期任务必须有合法 `recurrence_unit` 和 `next_due_at`。
- 暂停只用于周期任务；归档任务不占用主列表。

索引：`(user_id, deleted_at, status, due_at)`、`(user_id, next_due_at)`、`(user_id, manual_sort_order)`、`(user_id, title)` 用于归档搜索。

#### `task_completions`：任务完成历史

字段：`id`、`task_id`、`user_id`、`completion_type`（单日/周期）、`due_at`、`completed_at`、`created_at`。

索引：`(user_id, completed_at)`、`(task_id, due_at)`。完成历史不生成未来任务实例。

#### `reminders`：三类提醒

字段：`id`、`user_id`、`reminder_type`（`anniversary` / `health` / `payment`）、`title`、`content`、`recurrence_unit`（`once` / `day` / `week` / `month`）、`next_due_at`、`next_notify_at`、`remind_time`、`calendar_type`（公历/农历，可空）、`solar_month`、`solar_day`、`lunar_month`、`lunar_day`、`is_lunar_leap_month`、`amount_cents`（缴费专用，可空）、`status`（进行中/已完成/已暂停）、`last_completed_at`、`created_at`、`updated_at`。

约束与索引：

- 纪念日使用公历/农历字段及 `next_due_at`，默认 `next_notify_at` 提前 3 天。
- 健康提醒支持四种周期；单次提醒的 `next_due_at` 精确到分钟。
- 缴费提醒必须有非负 `amount_cents` 和日/周/月周期，默认提前 7 天。
- 索引：`(user_id, reminder_type, status)`、`(status, next_notify_at)`。

#### `reminder_completions`：提醒处理历史

字段：`id`、`reminder_id`、`user_id`、`action`（已缴/完成）、`due_at`、`amount_cents`（可空）、`completed_at`、`created_at`。

索引：`(reminder_id, due_at)`、`(user_id, completed_at)`。用于核对缴费顺延及历史导出。

#### `notes`：快速便签

字段：`id`、`user_id`、`content`、`is_completed`、`created_at`、`updated_at`。

索引：`(user_id, is_completed, created_at)`。无 `deleted_at`，删除即物理删除。

### 7.4 消息、调度、备份与日志

#### `notifications`：站内消息与推送状态

字段：`id`、`user_id`、`notification_type`（任务/纪念日/健康/缴费）、`source_type`、`source_id`、`title`、`content`、`dedup_key`（唯一）、`read_at`、`wecom_status`（无需推送/待推送/已送达/失败）、`push_attempts`、`last_push_error`、`pushed_at`、`created_at`、`updated_at`。

索引：`dedup_key` 唯一、`(user_id, read_at, created_at)`、`(wecom_status, created_at)`。

说明：同一消息记录站内状态和企微状态；已读满 30 天物理清理。

#### `scheduler_state`：调度状态

字段：`id`、`job_name`（唯一）、`last_run_at`、`last_success_at`、`last_error`、`last_duration_ms`、`updated_at`。

说明：系统状态读取此表；单次提醒轻量扫描和每日 8 点正式检查使用不同任务名，不为每条提醒建立独立调度任务。

#### `backup_download_tokens`：一次性备份下载令牌

字段：`id`、`token_hash`（唯一）、`created_by`、`storage_name`、`expires_at`、`used_at`、`created_at`。

说明：生成备份时使用 SQLite 在线备份 API；下载成功后令牌立即失效，临时文件按安全策略清理，不提供恢复页面。

#### `audit_logs`：安全审计

字段：`id`、`actor_user_id`、`action`、`target_type`、`target_id`、`detail_json`、`ip_address`、`created_at`。

索引：`(actor_user_id, created_at)`、`(action, created_at)`。至少记录备份生成和下载；禁止记录密码、Webhook、完整邀请码、令牌或密钥。

#### `alembic_version`：迁移版本

由 Alembic 维护，记录当前数据库结构版本，不手工编辑。

## 10. 里程碑与验收标准

每个实际开发轮次只实现用户当轮指定范围，不改已验收模块。每个功能交付时另附不少于 3 条浏览器验收用例，包含前置数据、点击路径和预期结果。

### M0：总纲与工程基线（当前轮，等待总纲确认后执行）

内容：五条协作规则、Flask 骨架、锁定依赖、`.gitignore`、中文 README、SQLite WAL、健康检查、迁移基线。

不做：安装向导、注册、登录、任务、提醒等业务功能。

验收：

1. 浏览器打开 `http://127.0.0.1:5000/healthz`，显示应用正常、数据库可用、WAL 已开启、时区为东八区。
2. 开发工程师重启应用后再次打开健康检查，结果仍正常，数据库和上传目录均位于 `data/`。
3. 依赖全部锁定版本，Git 不跟踪数据库、上传文件、备份、日志和密钥；README 有中文一键启动及成功判断方法。
4. 自动化检查确认迁移可执行、外键开启、WAL 在重连后有效；本轮完成后提交 Git 并用中文说明。

### M1：安装向导、用户、权限与邀请码

验收：

1. 首次访问能看到安装向导，依次设置管理员和网站名称后进入登录页；再次访问 `/install` 不能重复安装。
2. 错邀请码注册失败并显示中文提示；有效邀请码可注册两个普通账号，邀请码次数正确扣减。
3. 两个账号互看不到对方数据；普通用户访问 `/admin` 显示中文 403。
4. 同一账号连续输错密码 5 次后锁定 15 分钟；登录成功后会话 ID 更新，登录态有效期为 30 天。
5. 管理员关闭注册后注册入口和提交均不可用；重新开启后恢复；删除邀请码后该码立即失效。
6. 管理员禁用用户后无法继续操作和重新登录，数据保留；重置密码后旧登录态全部失效。

### M2：任务管理、回收站与手动排序

验收：

1. 新建昨天截止的待办任务后，任务标红并带文字，列表顶部出现逾期横幅；点击横幅可查看逾期任务。
2. 删除任务后进入回收站并显示剩余天数；恢复后回到原列表；彻底删除需确认。
3. 每日周期任务完成后下次日期自动顺延一天，不生成未来实例；每周和每月任务分别验证周期及月末规则。
4. 周期任务暂停后不再顺延和提醒，恢复后显示重新计算的下次到期时间。
5. 默认排序符合日期+优先级；切换手动模式后拖拽顺序保存，刷新页面仍保持。
6. 已完成任务归档后不占主列表，可在归档页按名称搜索；两个用户不能搜索或访问对方任务。
7. 本月总数、已完成、待完成、逾期和完成率与手工统计一致，周期任务不计入完成率分母。

### M3：三类提醒、消息中心、调度与企微

验收：

1. 新建农历纪念日并提前运行测试调度后，详情显示当年重新换算的公历日期；提前 3 天只生成一条消息，闰月示例符合定义。
2. 新建缴费提醒后，提前 7 天出现站内消息；标记已缴后自动顺延一个周期并保存本次金额和到期历史。
3. 新建每日/每周/每月健康提醒，分别验证下次时间；新建“5 分钟后”单次健康提醒，届时收到站内消息。
4. 填入有效企微 Webhook 后先点“测试连通”，企微收到中文测试消息；上述“5 分钟后”提醒到达时，企微收到消息且铃铛出现红点。
5. 不填写 Webhook 的另一用户只收到站内消息，无报错、不催填；任何页面均看不到 Webhook 明文。
6. 打开消息详情自动已读，未读红点更新；“全部已读”后未读数归零，消息可跳回来源。
7. 重复运行同一调度不重复推送；无效 Webhook 产生后台可见的中文失败摘要，系统状态更新最近成功/失败数。
8. 自动化测试验证正式任务每天东八区 8:00 运行、消息去重、已读 30 天清理和农历跨年换算。

### M4：仪表盘、快速便签、个人导出与管理后台

验收：

1. 准备今日任务、逾期任务和今日提醒后，仪表盘各卡片数据与任务/提醒页面一致，本月完成率进度条口径一致。
2. 学习状态卡片只显示占位说明，不可点击进入未开发模块。
3. 在仪表盘新建、编辑和完成便签，刷新后状态保留；删除前出现确认，删除后不出现在任务回收站。
4. 导出 JSON 后可用文本查看器打开，中文无乱码，包含格式版本和本人数据，不含 Webhook、密码哈希或其他用户数据。
5. 管理员更换网站名称及合法 PNG/JPG Logo 后全站导航生效；伪装图片、其他格式或超过 1MB 文件被中文提示拒绝。
6. 系统状态显示数据库大小、调度器上次运行时间、最近推送成功/失败数和用户数，与测试数据一致。
7. 管理员一键下载的 SQLite 备份可正常打开且完整性检查通过；一次性链接第二次使用失效，普通用户无法下载，下载动作有日志。

### M5：移动端、Zeabur 部署与上线自查

验收：

## 11. 每轮交付与验收方式

1. 每轮只做用户指定模块，禁止改动已验收的其他模块。
2. 每轮结束提交 Git，提交说明使用中文，列出实际变更和验证结果。
3. 每轮结束列出“本轮我自己做出的假设清单”。
4. 出现错误由开发工程师修复；需要用户操作时提供图形界面具体点击路径，不让用户改代码或敲命令。
5. 每个功能提供不少于 3 条浏览器验收用例，覆盖正常、异常和跨用户权限路径。
6. 开始前读取磁盘当前代码，不用旧设计或旧记忆覆盖新代码。
7. 如发现必须修改已验收模块的问题，先报告原因和影响，等待用户决定。

4. 禁用用户时同时撤销现有会话，但完整保留业务数据，重新启用后可登录。

7. 每日 8:00 是正式周期检查；调度器每分钟只轻量扫描已到期的单次提醒，不为每条提醒创建独立任务，每日检查负责补偿且必须去重。
8. 缴费周期沿用健康提醒的每日/每周/每月；金额以人民币元录入、以分存储。
9. 恢复已暂停周期任务时，按原周期重新计算未来的下次到期时间，不补跑暂停期间的多次提醒。

13. JSON 导出包含本人业务数据，不含敏感凭据；P0 不实现 JSON 导入。
14. 健康检查 `/healthz` 仅作为部署技术端点，不是新增用户功能。
15. 多设备同时编辑采用后保存覆盖先保存，页面显示最后更新时间。
